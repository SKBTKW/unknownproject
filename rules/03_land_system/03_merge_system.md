# 03. 地帯化・連携 — 現行仕様

> **Status:** Mostly implemented / Trial tactics connection partly planned
>
> プレイヤー向けには旧 `MERGE` を「地帯 / 地帯化」、旧 `LINK` を「連携」と呼ぶ。内部実装・セーブ互換では `merge*` / `mergeLinks` を維持する。

---

## 1. 地帯化の基本

地帯化は、4マスの土地が指定形状を完成したとき成立する。

現在実装済みの形状は、

- 共通: 2×2正方形
- 丘陵: L字4マス
- 山岳: 凸字 / T字4マス

である。

湿原および水源セルは地帯化対象外。

草原 `GL1_PLAINS` と干拓地 `E1_RECLAIMED_LAND` は `zoneCategory = PLAINS` を共有するため、混成2×2でも平地系地帯を成立できる。

---

## 2. 2×2地帯

```text
■ ■
■ ■
```

同じ地帯カテゴリの4マスが2×2を形成すると真の地帯となる。

成立時、4セルは同一 `mergeGroupId` を持ち、`yieldMultiplier = 1.20` のグループとして登録される。

### 現在の即時成立報酬

| 地帯 | 即時報酬 |
| :--- | :--- |
| 平地系 | 🌾+10 / 🔥+2 |
| 丘陵系 | 🌾+4 / 🧱+8 / 🔥+1 |
| 山岳系 | 🧱+10 / ✨+5 / 🔥+1 |
| その他 | 🌾+5 / 🔥+1 |

🔥成立報酬は `EmberSystem.addBonus()` を使用し、現在値が一時的にmaxEmberを超えることを許可する。

---

## 3. 持続産出

真の地帯に属する土地セルの基礎産出を合計し、

```text
ceil(土地セル合計 × 1.20)
```

を🌾・🧱・✨へ適用する。

重要:

> **ソケット産出は1.20倍の対象外。**

ProductionCalculatorでは、土地セル産出を地帯単位で1.20倍した後、ソケット産出を別途加算する。

🛡️についてもDefenseSystem側で盤面防衛値を導出するため、Productionの🌾/🧱/✨とは管理経路が異なる。

---

## 4. 丘陵L字地帯

丘陵4マスがL字を完成すると `L_SHAPE` 地帯が成立する。

実装は回転を含む8パターンを認識する。

### 成立報酬

```text
🌾+4
🧱+6
🔥+1
```

### 覚醒ソケット

最後に地帯を完成させたマスへ、

```text
SOCKET_HIDDEN_DEPOSIT
```

を付与する。

持続効果:

```text
🧱+2
🛡️+1
```

地帯オブジェクトには `isInterceptionPoint = true` と `keystoneCoord` が保存される。

ただし現行Trial Resolverがこのフラグを戦術効果として消費していることは確認できない。

したがって、

> **L字地帯そのものと覚醒ソケットは実装済み。専用伏兵戦術は未接続。**

と扱う。

---

## 5. 山岳凸字 / T字地帯

山岳4マスが凸字を完成すると `T_SHAPE` 地帯が成立する。

回転4パターンを認識する。

### 成立報酬

```text
🧱+8
✨+4
🔥+1
```

### 覚醒ソケット

最後に完成させたマスへ、

```text
SOCKET_SUMMIT_FORTRESS
```

を付与する。

持続効果:

```text
🛡️+3
✨+2
```

L字と同様、`isInterceptionPoint = true` は保存されるが、現行Trialの戦闘解決へ専用効果として接続されていることは確認できない。

よって、

> **山岳T字地帯と主峰砦は実装済み。専用籠城戦術は未接続。**

とする。

---

## 6. 同属性地帯の隣接制限

新たな2×2地帯を成立させた結果、既存の同属性地帯と直接面接触する場合、その土地配置を禁止する。

一方、地帯化していない1〜3マスの同属性土地が既存地帯へ接すること自体は許可する。

異属性地帯同士の面接触は許可し、連携判定対象となる。

---

## 7. 連携

連携は、

> **異なる属性の真の地帯同士が上下左右で接触したとき**

成立する。

対象は2×2 / L_SHAPE / T_SHAPE等の `isTrueMergedCell()` が真となる地帯。

単なる1×2 / 1×3接続グループは連携対象外。

同じ2地帯の組み合わせは接触辺数に関係なく1連携として、順序非依存のキーで `mergeLinks: Set` に記録する。

### 現在の連携報酬

新規連携1本につき、

```text
maxEmber +1
ember +1
```

を付与する。

実装順は、

1. `maxEmber` を+1
2. 現在🔥を+1回復

である。

1回の土地開発で複数連携が新規成立した場合、その本数分だけ加算する。

---

## 8. 連携の現在の役割と未実装領域

現在の直接効果は、

```text
🔥現在値 / 最大値の拡張
```

が中心。

以下は設計上重要だが、現在のgame実装では正本化しない。

- 連携数に応じたTrial同時正面数
- 地帯間資源流通
- Offeringカテゴリ補正
- 連携専用戦術
- 専用盤面描画

Trialでは将来的に、

> **連携が発達するほど多方面へ兵站・兵力を展開できる**

という意味を持たせる方向を維持する。

---

## 9. 地帯化済みセルの保護

真の地帯化済みセルは、恒久的な地形変更カードの対象から除外する方向で実装されている。

例:

- 伐採
- 干拓

など。

単なる1×2 / 1×3接続グループはこの保護対象ではない。

---

## 10. 本営近郊との重複

本営近郊セルでも条件を満たせば地帯化できる。

ProductionCalculatorでは、

- 地帯1.20倍
- 本営近郊の固定加算

を別経路で計算するため、両方が成立し得る。

---

## 11. Presentationとゲームルールを分離する

旧仕様にあった、

- 0.3秒固定フラッシュ
- 4セルを1枚の専用巨大スプライトへ置換

などはPresentation案であり、地帯成立のゲームルールではない。

見た目を変更しても、

```text
mergeGroupId
mergeType
yieldMultiplier
keystone socket
mergeLinks
```

というドメイン状態を正本とする。

## 12. Legacy / 未実装候補

以下は現行実装として確認できないため正本から外す。

- 周囲8マス包囲後の中央穴埋めで✨+10/T
- 中央穴埋めで🔥+2
- ソケット中央穴埋めの特殊分岐
- L字専用伏兵戦術の自動発動
- T字専用籠城戦術の自動発動
- 地帯専用巨大グラフィックへのルール依存

アイデア自体を削除する必要はないが、実装済み仕様として扱わない。

## 13. 実装SSOT

現在の主要実装は、

- `game/src/systems/grid_engine.js`
- `game/src/core/merge_rules.js`
- `game/src/systems/production_calculator.js`
- `game/src/systems/ember_system.js`

に分散している。

特に、

- 地帯成立判定 / 即時報酬 / 覚醒ソケット / 連携 → `GridEngine`
- 真の地帯判定 / 地帯属性互換 → `merge_rules.js`
- 1.20倍持続産出 → `ProductionCalculator`
- 🔥現在値 / maxEmber → `EmberSystem`

という責務分担になっている。
