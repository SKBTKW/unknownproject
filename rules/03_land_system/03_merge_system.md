# 03. 地帯化・連携 — 現行仕様

> **Status:** Mostly implemented / runtime discrepancies recorded
>
> プレイヤー向けには旧 `MERGE` を「地帯 / 地帯化」、旧 `LINK` を「連携」と呼ぶ。内部実装・セーブ互換では `merge*` / `mergeLinks` を維持する。

---

## 1. 地帯化の基本

地帯化は、4マスの土地が指定形状を完成したとき成立する。

現在の正本形状は、

- 共通: 2×2正方形
- 丘陵: L字4マス
- 山岳: 凸字 / T字4マス

である。

湿原および水源セルは地帯化対象外。

草原 `GL1_PLAINS` と干拓地 `E1_RECLAIMED_LAND` は `zoneCategory = PLAINS` を共有するため、混成2×2でも平地系地帯を成立できる。

重要:

> **game内部には1×2 / 1×3の同地形接続グループも存在するが、正本上の「地帯」ではない。**

---

## 2. 2×2地帯

```text
■ ■
■ ■
```

同じ地帯カテゴリの4マスが2×2を形成すると真の地帯となる。

成立時、4セルは同一 `mergeGroupId` を持ち、`mergeType = "2x2"`、`yieldMultiplier = 1.20` のグループとして登録される。

### 現在の即時成立報酬

| 地帯 | 即時報酬 |
| :--- | :--- |
| 平地系 | 🌾+10 / 🔥+2 |
| 丘陵系 | 🌾+4 / 🧱+8 / 🔥+1 |
| 山岳系 | 🧱+10 / ✨+5 / 🔥+1 |
| その他 | 🌾+5 / 🔥+1 |

🔥成立報酬は `EmberSystem.addBonus()` を使用し、現在値が一時的にmaxEmberを超えることを許可する。

---

## 3. 持続産出

### 正本

真の地帯に属する土地セルの基礎産出を合計し、

```text
ceil(土地セル合計 × 1.20)
```

を🌾・🧱・✨へ適用する。

重要:

> **ソケット産出は1.20倍の対象外。**

### 現gameの内部不一致

現 `ProductionCalculator.calculateTotalProduction()` は、真の地帯判定 `isTrueMergedCell()` や `cell.merged === true` を使用せず、

```text
cell.mergeGroupId が存在する
```

だけでグループ産出へ入れ、そのグループ合計を1.20倍する。

一方、`GridEngine.checkConnectionBonus()` は正本上の地帯ではない1×2 / 1×3接続グループにも `mergeGroupId` を付与する。

そのため現runtimeでは、

> **1×2 / 1×3接続グループまで🌾・🧱・✨の1.20倍対象になってしまう。**

これは現正本ルールではなく、**game内部のgroup表現とProduction判定の責務衝突**として扱う。

🛡️は `DefenseSystem.calculateMaxDefense()` が各土地の防衛値を直接合算しており、現時点では地帯の1.20倍を適用していない。したがってProduction表示/産出と最大🛡️で地帯倍率の扱いも一致していない。

---

## 4. 1×2 / 1×3接続グループ — Legacy-compatible runtime behavior

現 `GridEngine.checkConnectionBonus()` には、同じ地形属性の別配置ブロックが面接触した際に1×2 / 1×3接続グループを作る処理が残っている。

これは正本上の地帯化ではないが、現在のgameでは実際に以下を行う。

- `mergeGroupId` を付与
- `mergeType = "1x2" / "1x3"` を設定
- `mergedBlocks` へgroupを登録
- `yieldMultiplier = 1.0` として保存
- 初回接続pairごとに即時資源ボーナスを付与

### 1×2 即時ボーナス

| 地形 | 即時報酬 |
| :--- | :--- |
| 砂漠 | ✨+1 |
| 平地 | 🌾+3 |
| 森 | 🌾+1 / 🧱+1 |
| 深い森 | 🧱+2 / ✨+1 |
| 砂漠丘陵 | 🧱+1 / ✨+1 |
| 丘陵 | 🌾+2 / 🧱+1 |
| 森丘陵 | 🧱+3 |
| 深い森丘陵 | 🧱+4 / ✨+1 |
| 山岳 | 🧱+4 / ✨+1 |

### 1×3 即時ボーナス

| 地形 | 即時報酬 |
| :--- | :--- |
| 砂漠 | ✨+3 |
| 平地 | 🌾+6 |
| 森 | 🌾+3 / 🧱+3 |
| 深い森 | 🧱+5 / ✨+3 |
| 砂漠丘陵 | 🧱+3 / ✨+3 |
| 丘陵 | 🌾+5 / 🧱+3 |
| 森丘陵 | 🌾+2 / 🧱+6 |
| 深い森丘陵 | 🧱+8 / ✨+3 |
| 山岳 | 🧱+8 / ✨+3 |

ただしこの1×2 / 1×3ボーナスは、現在の上位設計でいう「開発 → 地帯化 → 連携」の地帯化報酬としては採用確定扱いしない。

正本上は、

> **1×2 / 1×3 = gameに残る旧接続グループ処理。4マス地帯とは別物。**

として監査対象にする。

## 5. 丘陵L字地帯

丘陵4マスがL字を完成すると `L_SHAPE` 地帯が成立する。

実装は回転を含む8パターンを認識する。

### 成立報酬

```text
🌾+4
🧱+6
🔥+1
```

### 覚醒ソケット

最後に地帯を完成させたマスへ、

```text
SOCKET_HIDDEN_DEPOSIT
```

を付与する。

持続効果:

```text
🧱+2
🛡️+1
```

地帯オブジェクトには `isInterceptionPoint = true` と `keystoneCoord` が保存される。

ただし現行Trial Resolverがこのフラグを戦術効果として消費していることは確認できない。

したがって、

> **L字地帯そのものと覚醒ソケットは実装済み。専用伏兵戦術は未接続。**

と扱う。

## 6. 山岳凸字 / T字地帯

山岳4マスが凸字を完成すると `T_SHAPE` 地帯が成立する。

回転4パターンを認識する。

### 成立報酬

```text
🧱+8
✨+4
🔥+1
```

### 覚醒ソケット

最後に完成させたマスへ、

```text
SOCKET_SUMMIT_FORTRESS
```

を付与する。

持続効果:

```text
🛡️+3
✨+2
```

L字と同様、`isInterceptionPoint = true` は保存されるが、現行Trialの戦闘解決へ専用効果として接続されていることは確認できない。

よって、

> **山岳T字地帯と主峰砦は実装済み。専用籠城戦術は未接続。**

とする。

---

## 7. 同属性地帯の隣接制限

新たな2×2地帯を成立させた結果、既存の同属性地帯と直接面接触する場合、その土地配置を禁止する。

一方、地帯化していない1〜3マスの同属性土地が既存地帯へ接すること自体は許可する。

異属性地帯同士の面接触は許可し、連携判定対象となる。

---

## 8. 連携

連携は、

> **異なる属性の真の地帯同士が上下左右で接触したとき**

成立する。

対象は2×2 / L_SHAPE / T_SHAPE等の `isTrueMergedCell()` が真となる地帯。

単なる1×2 / 1×3接続グループは連携対象外。

同じ2地帯の組み合わせは接触辺数に関係なく1連携として、順序非依存のキーで `mergeLinks: Set` に記録する。

### 現在の連携報酬

新規連携1本につき、

```text
maxEmber +1
ember +1
```

を付与する。

実装順は、

1. `maxEmber` を+1
2. 現在🔥を+1回復

である。

1回の土地開発で複数連携が新規成立した場合、その本数分だけ加算する。

---

## 9. 連携の現在の役割と未実装領域

現在の直接効果は、

```text
🔥現在値 / 最大値の拡張
```

が中心。

以下は設計上重要だが、現在のgame実装では正本化しない。

- 連携数に応じたTrial同時正面数
- 地帯間資源流通
- Offeringカテゴリ補正
- 連携専用戦術
- 専用盤面描画

Trialでは将来的に、

> **連携が発達するほど多方面へ兵站・兵力を展開できる**

という意味を持たせる方向を維持する。

---

## 10. 地帯化済みセルの保護

真の地帯化済みセルは、恒久的な地形変更カードの対象から除外する方向で実装されている。

例:

- 伐採
- 干拓

など。

単なる1×2 / 1×3接続グループはこの保護対象ではない。

---

## 11. 本営近郊との重複

本営近郊セルでも条件を満たせば地帯化できる。

ProductionCalculatorでは、

- 地帯1.20倍
- 本営近郊の固定加算

を別経路で計算するため、両方が成立し得る。

ただし前述の通り現runtimeでは `mergeGroupId` を持つ1×2 / 1×3もProduction側の1.20倍へ混入するため、ここでいう「地帯1.20倍」は正本上の意味とruntime対象範囲が一致していない。

---

## 12. Presentationとゲームルールを分離する

旧仕様にあった、

- 0.3秒固定フラッシュ
- 4セルを1枚の専用巨大スプライトへ置換

などはPresentation案であり、地帯成立のゲームルールではない。

見た目を変更しても、正本上は、

```text
mergeGroupId
mergeType
yieldMultiplier
keystone socket
mergeLinks
```

等のドメイン状態を参照する。

ただし `mergeGroupId` は現在1×2 / 1×3にも再利用されているため、**`mergeGroupId`単独を真の地帯判定に使わない**ことが重要。

## 14. 実装SSOTと確認済み内部齟齬

現在の主要実装は、

- `game/src/systems/grid_engine.js`
- `game/src/core/merge_rules.js`
- `game/src/systems/production_calculator.js`
- `game/src/systems/defense_system.js`
- `game/src/systems/ember_system.js`

に分散している。

確認済みの重要な内部齟齬:

1. `GridEngine` は1×2 / 1×3にも `mergeGroupId` を付与する。
2. `merge_rules.js` 上の真の地帯は4マス形状を前提とする。
3. `ProductionCalculator` は `mergeGroupId` の存在だけで1.20倍対象にするため、1×2 / 1×3まで倍率対象になる。
4. `DefenseSystem` は現状この1.20倍を最大🛡️へ適用しない。
5. `checkNewMergeLinks()` は真の地帯判定を利用するため、1×2 / 1×3は連携対象外。

したがって現在は、**「mergeGroup」という内部表現が、接続グループと真の地帯の二用途に使われていること**が主要な齟齬源になっている。
