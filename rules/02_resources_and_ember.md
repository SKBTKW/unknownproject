## 2. 🔥残火の状態

`EmberSystem` は現在値 `ember` と容量 `maxEmber` を分離して管理する。

初期値は、

```text
ember = 20
maxEmber = 20
```

とする。

### 2.1 状態区分

| 🔥現在値 | 状態 | 食料維持費 | 追加効果 |
| :--- | :--- | ---: | :--- |
| 0〜9 | CRISIS | 🌾15 | 旺盛ボーナスなし |
| 10〜23 | STANDARD | 🌾20 | 標準 |
| 24以上 | PROSPEROUS | 🌾25 | 産出×1.10、✨+2固定加算 |

PROSPEROUSの倍率は現在、🌾・🧱・✨のProduction計算へ適用される。

🔥0は敗北条件として扱う。Trialによる本営損害については `05_trials_and_defense.md` を参照。

## 3. Verse終了時の🔥自然変動

配置済み領土マス数とStageに応じて、毎Verseの自然変動が決まる。

| Stage | 減衰停止 | 自家発熱 |
| :--- | ---: | ---: |
| Stage 1 / 5×5 | 8マス | 20マス |
| Stage 2 / 7×7 | 24マス | 40マス |
| Stage 3 / 9×9 | 48マス | 68マス |

処理は、

```text
領土 < 減衰停止       → 🔥-1
減衰停止以上          → ±0
自家発熱以上          → 🔥+1
```

とする。

一部カード効果により負の自然減衰を軽減できる。

## 4. Hold維持費

保留スロットにカードが存在する場合、通常はVerseごとに、

```text
🔥-1
```

の維持費を追加する。

《再燃》などにより `reserveFeeWaivedTurns` が有効な期間は、このHold維持費を0にできる。

自然変動、Hold維持費、恒常回復は `EmberSystem.calculateTurnBalance()` で合算される。

## 5. 🔥回復と最大容量

現在の実装では以下を区別する。

### 通常回復

`recoverInstant(amount)` は原則 `maxEmber` まででクランプする。

### 上限超過許可ボーナス

`addBonus(amount)` は `allowOvercap=true` の即時回復として扱い、現在値を一時的に `maxEmber` より上へ持ち上げられる。

地帯化成立報酬などはこの経路を使用する。

### 最大容量増加

`expandMaxCapacity(amount)` により `maxEmber` 自体を増加できる。

現在、最大容量という概念は実装済みだが、どのゲーム要素を正式な容量拡張源とするかは土地・連携仕様側で管理する。

したがって、

> **「🔥は最大値なし」ではない。**

現在値の一部ボーナスだけが一時的な上限超過を許可する。

## 6. 食料Productionと維持費決済

Verse終了時の食料処理では、ProductionとMaintenanceを二重に引かない。

正式な流れは、

```text
現在🌾
+ grossFood
- 最終維持費
= Verse終了後🌾
```

とする。

`ProductionCalculator` の意味は、

- `grossFood`: 実際にstateへ加算する総食料産出
- `foodCost`: 最終維持費
- `netFood`: `grossFood - foodCost` の表示用純収支

である。

`netFood` をstateへ加算した後に維持費を再度引いてはならない。

---

## 7. 食料不足時の自動補填

維持費支払い後に食料不足が発生する場合、現在の補填レートは、

```text
✨1 = 🌾6
🧱5 = 🌾1
```

である。

優先順は、

```text
✨ → 🧱
```

とする。

ただし最重要ルールとして、

> **不足を完全に埋められる場合だけ自動補填を実行する。**

不足が1以上残る場合は✨・🧱を一切消費しない。

完全補填できない場合、通常の飢餓ペナルティとして🔥-1を受ける。

この仕組みは「✨万能変換」ではなく、食料破綻を回避する非常手段とする。

## 8. 土地開発時の🔥コスト

土地カードの開発コストは一律🔥1ではない。

現在は配置済み**ブロック数**に応じて段階化される。

| 既配置ブロック数 | 次の土地開発コスト |
| :--- | ---: |
| 0〜5 | 🔥0 |
| 6〜15 | 🔥1 |
| 16〜30 | 🔥2 |
| 31以上 | 🔥3 |

コストはShapeのマス数ではなく、土地ブロックを何回開発したかで決まる。

土地配置成功後にコストを支払い、`placedBlockCount` を1増加する。

## 9. 地帯化による即時資源

同属性接続および地帯化では、通常Productionとは別に即時資源を受け取る場合がある。

### 2×2地帯化

現在の主要な成立報酬は以下。

| 地帯 | 即時報酬 |
| :--- | :--- |
| 平地系 | 🌾+10 / 🔥+2 |
| 丘陵系 | 🌾+4 / 🧱+8 / 🔥+1 |
| 山岳系 | 🧱+10 / ✨+5 / 🔥+1 |
| その他 | 🌾+5 / 🔥+1 |

成立した4マス地帯の通常持続産出は `×1.20`。

丘陵L字、山岳凸字などの異形地帯にも個別の成立報酬が存在する。詳細は `03_land_system/03_merge_system.md` を正本とする。

## 10. 🛡️防衛は「最大値」と「現在値」を分離する

現在の防衛システムでは、

```text
maxDefense
currentDefense
```

を分離する。

### maxDefense

盤面から導出される防衛容量。

主な構成要素は、

- 本営防衛
- 各土地の🛡️
- ソケットの🛡️
- 本営近郊恒久ボーナス
- `defenseCapacityBonus`
- 一時的なVigilance補正

である。

### currentDefense

現在実際に保有している防衛プール。

Trialへ持ち込めるのは、

```text
currentDefense
```

であり、`maxDefense` そのものではない。

土地配置等でmaxDefenseが変わった際、currentDefenseは新maxを超えないようreconcileされる。

## 11. 🛡️再建

DefenseSystemには、Trial等で失ったcurrentDefenseをmaxDefenseまで回復する再建APIが存在する。

ただし現在、通常ゲームへ注入される正式な `rebuildCostResolver` は未確定である。

そのため、

```text
REBUILD_COST_UNDEFINED
```

となり得る。

よって、

> **防衛再建のシステム骨格は実装済みだが、正式なゲームプレイコストは未確定。**

と扱う。

## 13. ✨神秘

✨の詳細な役割は `07_mysticism_and_desert.md` を参照する。

資源正本として重要なのは、

- Verse維持費として自動消費されない
- 食料不足時の補填候補になる
- 神秘カードの支払いに使う
- 地形・ソケット・地帯化等から産出される

という点である。

砂漠の通常土地カードについては、地形マトリクス上の値ではなく、現在実際に配置される `LAND_CARDS_MASTER` の値がProductionへ入る。現在 `CARD_DESERT_1X1 / 1X2` は1マスあたり✨5を持つ。

## 14. 廃止済み・Legacy

以下を現在の資源正本から外す。

- 土地を直接クリックして🔥1で探索する常設アクション
- ブロックサイズによる探索2D6補正
- 出目12だけ自然目必須という旧探索専用ルール
- 「✨1000+で奇跡」のような固定蓄積アンロック
- 一律🔥1の土地配置コスト
- 🛡️を単一値だけで扱う旧仕様

2D6そのものは廃止していない。汎用判定基盤として `CheckSystem` に残り、《放棄された集落》や将来のTrial戦術等で使用できる。

## 15. 実装上の既知課題

### A. 土地産出定義の重複

`land_system.js` と `land_cards_data.js` に同じ地形について異なる産出値が存在する。

特に砂漠は、

```text
TERRAIN_MATRIX: ✨2
LAND_CARDS_MASTER: ✨5
```

で不一致。

通常土地カード配置では後者が実産出になる。

### B. 資材内部名

`wood` と `material` が併存している。ゲームプレイ上は🧱資材として統一するが、内部互換コードが残る。

### C. Defense再建費

APIは存在するが正式なコストResolverが未確定。

### D. Stage 3 HQ産出

Stage 2拡張時の14/14/14/2は実装済みだが、Stage 3用の別定義は確認できていない。
